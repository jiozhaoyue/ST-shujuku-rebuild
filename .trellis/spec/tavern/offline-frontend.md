# 前端离线化：零 CDN、单文件、`file://` 可运行

> 本页属**酒馆仓群跨仓工程约定**（由 `tavern-harness` 市场模板 `tavern-spec` 分发）。
> 面向：面向用户交付的**前端页面、单文件工具、原型**。对应项目既定的三条前端偏好
> （零外部依赖 / 单文件原型 / 双击即运行）。

## 不变量（一句话）

**产物必须双击即用**：无网络、无构建服务器、无同源服务器时也完整可用。

---

## 判据（能跑才算合规）

### 1. 零外部依赖（nocdn）

```bash
# 交付物里不得有指向外部主机、会被浏览器自动拉取的资源
grep -rEn "src=\"https?://|href=\"https?://|@import\s+url\(https?://|cdn\." \
  --include="*.html" --include="*.css" --include="*.js" <交付目录>
```

**期望**：零命中。
**例外**（不算违规，但要在文件顶部注释说明）：纯文本形式的超链接（`<a href="https://…">` 用户点击才跳转）、
文档正文里引用的网址、`package.json` 里的依赖声明。

### 2. 单文件自包含（htmlone）

判据：独立页面/原型默认交付**单个 HTML 文件**，CSS 与 JS 内联于该文件。
需要多文件时（如模块较多）必须给出理由，且仍满足判据 1 与 3。

### 3. `file://` 协议可运行（htmlc2r）

```bash
# 静态检查：不得用会被 file:// 拦下的相对网络请求
grep -rEn "fetch\(\s*['\"]\./|fetch\(\s*['\"][^h]|new Worker\(\s*['\"]\./|import\(\s*['\"]\./" <交付目录>
```

**期望**：零命中。
**首选替代**：把数据内联为 JS 对象/`<script type="application/json">`；
需要多文件资源时用 `FileReader`（用户选择文件）或 `data:`/`blob:` URL。

**人工验证（必做一步）**：把产物复制到临时目录，直接用 `file://` 打开，确认
① 页面完整渲染；② 核心交互可用；③ 控制台无跨源/网络错误。

---

## 允许

- 内联的 base64 图片、内联字体、内联 SVG。
- 单个 `.html` 里塞下全部逻辑（含数据处理的纯前端算法）。
- 用宿主已提供的全局对象（在宿主内运行时）。

## 禁止

- 任何 CDN 样式/脚本/字体（含"仅作为回退"的 CDN 引用）。
- 依赖本地服务器才能运行（`localhost` 请求、模块热更新服务器、相对路径 fetch）。
- 把构建产物与源码混放导致用户拿到不可直接打开的目录结构。

---

## 证据锚点

- 三条偏好来自项目长期实践（零外部依赖 / 单文件原型 / 双击即运行），已在用户级规则中固化。
- 反面案例形态：产物在开发机（有本地服务器）一切正常，用户双击打开却是空白页或功能哑火——
  根因几乎总是"相对路径的运行时网络请求"被 `file://` 的同源策略拦下。

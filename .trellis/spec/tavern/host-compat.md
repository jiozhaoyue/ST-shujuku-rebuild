# 跨宿主兼容：判定与边界

> 本页属**酒馆仓群跨仓工程约定**（由 `tavern-harness` 市场模板 `tavern-spec` 分发）。
> 定位：**可机械检查的层内约定**。跨项目流程编排见 skill `tavern-host-compat`；
> 强制规则见规则块（`AGENTS.md` 的 `TAVERN_RULES` 块）L0-9 / L0-12 / P-13。

## 适用范围

需要跨宿主运行的插件/扩展。本仓群的四个宿主：**SillyTavern / Luker / PureTavern / TauriTavern**。

---

## 判据（能跑才算合规）

### 1. 用到宿主能力前，先确认该能力在本宿主可用

```bash
# 找出代码中所有宿主能力调用点（按项目实际 API 名调整模式）
grep -rn "window\.SillyTavern\|getContext()\|STAuthority" --include="*.ts" --include="*.js" src/ | head -50
```

对每个调用点回答两个问题并写进 PR 描述或任务产物：
1. 该能力在**四个宿主**分别可用吗？
2. 不可用时走哪条降级路径？

### 2. 宿主差异必须集中在单一 host-bridge 模块

```bash
# 业务层不得出现宿主名判断（应全部收在 host-bridge 内）
grep -rn "luker\|Luker\|PureTavern\|TauriTavern\|isSillyTavern\|hostName" --include="*.ts" --include="*.js" src/ \
  | grep -v -i "host-bridge\|hostBridge" | head -20
```

**期望**：除 host-bridge 模块外零命中。有命中即为违规——新增宿主会导致全仓大改。

### 3. 禁止翻宿主源码找内部函数

宿主源码里的内部函数**不是公开契约**，随版本可改。API 事实以**官方文档**为准。
判据：代码注释或 PR 里若引用了宿主内部文件路径（`public/scripts/...` 之类）作为依据，视为违规；
应改为引用官方文档或宿主公开导出的符号。

---

## 允许

- 用宿主**公开导出**的函数、事件、DOM 锚点、扩展 API。
- 在 host-bridge 内对宿主做版本/能力探测，并对上层给出统一抽象。
- 在 host-bridge 内用版本门禁拒绝不支持的宿主（拒绝即降级，不是崩溃）。

## 禁止

- 业务层出现宿主名判断（违反隔离，见判据 2）。
- 直接操作宿主内部 DOM 结构或调用未公开的内部函数。
- 依赖**宿主补丁类**能力来实现跨宿主插件的核心功能（如需要逐宿主打补丁的桥接层）——
  跨宿主插件只允许使用与宿主解耦的能力子集，并在代码里标注所用能力在各宿主的可用性。

---

## 证据锚点

- 宿主能力矩阵与降级链：见 skill `tavern-host-compat`（含四宿主对照与判定流程）。
- 真实事故：跨宿主插件依赖宿主补丁类能力 → 在某一宿主上被版本门禁静默拒绝，
  表现为"功能时好时坏"而非报错（规则块 P-13 同类；L0-12 的立法依据）。
- 样式注入的宿主污染事故与"双前缀"约定：规则块 L0-10 / P-5。

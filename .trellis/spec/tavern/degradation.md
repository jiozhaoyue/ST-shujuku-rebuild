# 可选后端：适配器 + 特性检测 + 静默降级

> 本页属**酒馆仓群跨仓工程约定**（由 `tavern-harness` 市场模板 `tavern-spec` 分发）。
> 面向：**纯前端项目引入服务端能力**（如接入 Authority 等可选后端）的场景。
> 强制规则见规则块 L0-11；接入 Authority 的具体流程见 skill `tavern-authority-integration`。

## 不变量（一句话）

**后端不可用时，纯前端路径必须保持全功能。** 后端是增强项，不是前置条件。

---

## 判据（能跑才算合规）

### 1. 纯前端路径不因后端缺失而阻塞

```bash
# 找出所有后端调用点，逐个确认：失败路径是否只降级、不抛断主流程
grep -rn "fetch(\|STAuthority\|authority" --include="*.ts" --include="*.js" src/ | head -50
```

**期望**：每个调用点满足其一——① 在 try/catch 或 `.catch()` 内且 catch 分支只 `console.warn` + 走本地路径；
② fire-and-forget（不 await 其结果决定渲染）。
**违规**：`await` 后端结果后再决定是否渲染主界面；或后端失败导致功能不可用。

### 2. 适配器通过依赖注入接缝接入，核心层不感知后端

```bash
# 核心状态机/业务模块不应直接 import 后端客户端
grep -rn "import .*authority\|from .*authority" --include="*.ts" src/core src/state 2>/dev/null | head
```

**期望**：核心层只依赖一个抽象接缝（如 `{save, load, remove}` 形态的接口），后端实现由外层注入。
**违规**：核心模块里出现后端 SDK 的 import 或全局对象访问。

### 3. 特性检测而非版本假设

判据：降级分支的触发条件是**运行时探测结果**（存在性/探针请求/能力查询），
而不是"猜测某宿主/某版本没有该能力"。探测结果应可缓存，避免每次调用都探。

### 4. 卸载后可回退到纯前端，历史数据不孤儿

判据：卸载可选后端后，此前保存的数据要么在本地存储仍可读，要么有显式的一次性导出/回退路径。
**违规**：数据只存在于后端专有库中，卸载即不可访问。

---

## 允许

- 后端可用时增强（服务端持久化、跨页签共享、大文件 Blob、后台任务、事件推送）。
- 启动时一次探针 + 结果缓存。
- 后端调用失败记入 `console.warn` 级别的日志，便于排障但不惊扰用户。

## 禁止

- 把"浏览器存储"当**事实源**（用户资产必须落在服务端原生目录或宿主原生存储；见下"证据锚点"）。
- 在核心层直接 `import` 后端客户端，或把后端可用性写成全局布尔标记散落各处。
- 静默吞掉后端错误到完全无痕（至少要有一条 warn，且能在排障面板看到）。
- 用后端能力**替代**前端必要功能（例如把必须可离线使用的功能做成依赖后端）。

---

## 证据锚点

- 真实返工事故：某仓曾按"浏览器优先"设计媒体存储，被纠正为"媒体从设计上就该存服务端原生目录"，
  随后做了存储倒置重构（规则块 P-9）。
- 样板实现：Authority 自身即此范式的样板——宿主桥接失败仅 `console.warn`，不阻断插件加载。
- 两个仓**各自独立收敛**到同一模式，说明这是项目的既定设计偏好而非偶然。

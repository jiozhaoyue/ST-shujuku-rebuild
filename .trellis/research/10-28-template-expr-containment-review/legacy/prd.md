# 模板表达式 new Function 收口（候选评审，未裁定不动工）

## Goal

对 template-vars 表达式引擎中 6 处 `new Function` 动态求值做**安全收口方案的评审与裁定**，
产出决策记录（含选定方案、影响面、迁移路径）。**本任务是评审态：未获用户对方案的明确裁定前，不写任何实现。**

## 背景

- 2026-10-28 夜班盘点：`new Function` 共 6 处，全部集中在表达式引擎——
  - `src/service/runtime/template-vars/var-store-and-tags.ts:251`（模板表达式求值）
  - `src/service/runtime/template-vars/sql-query-var.ts:837 / :985`（Proxy + new Function 执行 DB 链式表达式）
- 这是插件的**设计内脚本特性**（模板变量允许用户写 JS 表达式），不是漏洞误用。
- 但它意味着：任何能写入模板/表达式的输入都在宿主页面上下文里执行任意 JS。
  风险面与「谁有权写模板」有关——单人自用风险可控，多人共享/导入他人模板时有注入面。

## Requirements

- **R1 输入源盘点**：六处调用点的可达输入源梳理清楚（谁能通过什么 UI/导入路径写入表达式）。
- **R2 方案落档**：四方案（见下）的影响面/工作量/兼容风险逐项落档，给出推荐与理由。
- **R3 用户裁定**：方案必须经用户明确裁定（AskUserQuestion 或等价交互）后方可进入实现立项。
- **R4 决策持久化**：裁定结果记入本 PRD 与 `.trellis/spec/`。

### 候选方案（待裁定）

| 方案 | 说明 | 优点 | 代价/风险 |
| --- | --- | --- | --- |
| A. 维持现状 + 文档明示 | 在模板编辑 UI/文档标注「表达式=任意 JS，勿导入不可信模板」 | 零破坏 | 无实质收口 |
| B. 守卫式收口（保留语义） | 求值前静态扫描表达式，拒绝明显危险模式（`fetch`/`XMLHttpRequest`/`import`/localStorage 等）+ 可配置白名单开关 | 非白名单行为不变，默认更安全 | 黑名单天然可绕过；扫描误伤合法表达式 |
| C. 受限解释器 | 自写表达式子集解释器（属性访问/比较/算术/白名单函数调用） | 真收口 | 工程量大；复杂表达式语义漂移 → **既有用户模板破坏（数据兼容红线）** |
| D. Worker 沙箱 | 表达式移入 Web Worker 执行 | 隔离 DOM/网络策略可控 | DB 代理对象无法跨 Worker 传递；通信复杂度与延迟 |

## 约束

- **C1 数据兼容**：任何方案不得改变既有合法表达式的求值结果（上游模板 JSON 同构不动）。
- **C2 默认不破坏**：收口开关若引入，默认值必须与现行为一致或经用户明示选择。
- **C3 上游同构**：表达式引擎是上游共有部分；我方差量会加大追平冲突面，方案需评估台账影响。
